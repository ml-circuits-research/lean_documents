# Which stock should be counted?

A small HTML stock register lists active, quarantined and archived items. Check a report about the total and permission to release an item.

**Question:** Does the report count the right rows and apply the release rule correctly?

Upload the original HTML stock register and one stock report. Choose either [the careful report](report-correct.md) or [the report with deliberate errors](report-mixed.md) and audit it separately against all files in [sources/](sources/). No separate brief is needed; derive the questions from the report and source rules.

The audit can check included rows, totals, release conditions and whether the stated reasoning supports the conclusion. It reviews the supplied report, including its reasons and citations; it does not write the original report.

The snapshot contains no clearance history. Extracted HTML must be checked against the original rather than assumed complete.

These are fictional examples. Keep this guide, the alternate report, metadata, generation files and evaluator material outside the audit input. Evaluator expectations are withheld during a blind audit; the selected report and source documents are always available.

Historical execution records are indexed under [validation/runs](../../validation/runs/). This guide does not constitute a new validation run. Original reports and sources retain their bytes so they can be matched to prior results. New runs belong under `tmp/audit-runs/`, with a separate directory for each report.
