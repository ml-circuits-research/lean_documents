# What can an empty file tell us?

A supplier clearance report arrives with an empty evidence file. Check what the report can responsibly say about the supplied material.

**Question:** Can either clearance outcome be established from an empty source file?

Upload the supplied zero-byte file in sources/ and one clearance report. Choose either [the careful report](report-correct.md) or [the report with deliberate errors](report.md) and audit it separately against all files in [sources/](sources/). No separate brief is needed; derive the questions from the report and source rules.

The audit can check what was actually supplied and whether the report gives a basis for its clearance claims. It reviews the supplied report, including its reasons and citations; it does not write the original report.

There is no source text to quote. Missing evidence must not be turned into a finding that the supplier passed or failed.

These are fictional examples. Keep this guide, the alternate report, metadata, generation files and evaluator material outside the audit input. Evaluator expectations are withheld during a blind audit; the selected report and source documents are always available.

Historical execution records are indexed under [validation/runs](../../validation/runs/). This guide does not constitute a new validation run. Original reports and sources retain their bytes so they can be matched to prior results. New runs belong under `tmp/audit-runs/`, with a separate directory for each report.
