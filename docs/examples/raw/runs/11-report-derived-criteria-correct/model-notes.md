# Source-to-model correspondence

The model uses Lean 4.24.0 core only. `Campaign.Dispatch` enumerates exactly A, B, C, D, matching dispatch-ledger L-01 (generated P02). L-02 completeness and actual occurrence are source-ledger P03; the table itself is P04. This is a nonempty cohort with four actual dispatches, not an empty-domain universal. No inferred completeness extends to the other 36 campaign dispatches.

`amount`, `release`, `approval`, `routeR2`, `declaration`, `checksum`, and `listed` transcribe the four rows. Amounts are exact integer euro cents; dates are integer campaign-day indices per dispatch-policy P-01 (generated P02). `declaration = none` means no declaration through cutoff per L-02, not unknown. Approval is the sole event and fields are complete through cutoff, so C cannot acquire an invented alternate approval. `listed` is true for North/South and false for East using destination-list D-01 (generated P02), whose membership is expressly complete through days 1–20. Checksum is only PASS; its semantics are not extended to reliability or acceptance.

`ordinary` uses strict approval < release per policy P-02 (generated P03). `exception` is a conjunction of R2, inclusive 10 ≤ release ≤ 14, an existing declaration t with t ≤ release ≤ t+2, and release ≤ approval ≤ release+3 per P-03 (generated P04). `compliant` is their disjunction because P-03 says no other route applies to this cohort. `eligible` is compliant AND checksum PASS AND listed destination, exactly the P-04 biconditional (generated P05). Acceptance is not included, as explicitly instructed by P-04. For this final snapshot all recorded events used in the tests occurred no later than day 20; the model does not need a separate prospective cutoff filter.

`cohortTotal`, `eligibleAmount`, and `settlementTotal` sum each in-scope amount once, consistent with P-05 (generated P06). `total` gives 50000; `balance` subtracts it from the L-01 budget 55000 using integers. `bException` checks the conjunction for B (12 release, 11 declaration, 15 approval). `cNoncompliant` excludes both routes for C (12 release, 16 approval). `bEligible` additionally checks PASS and South. `eligibleExactly` checks all four constructors and finds exactly A/B. `settlement` sums their amounts to 30000. `outsideWindow` excludes release day 15 from [10,14]; it does not exclude ordinary approval on day 14 for D.

The model also contains intermediate theorems about individual eligibility and timing, used as readable checks; only explicitly referenced theorems are deliverable formal results with target assertion and axiom logs.

# Auxiliary missing-information witnesses

`laterCompatible` intentionally imposes no condition on a hypothetical later incident count. Packet-register K-01/K-02 (generated P02/P03) explicitly limit records to day 20 and provide no days 21–50 observations, and ledger L-03 denies reliability attestation. Reading the whole packet establishes that lack of a constraint; defining `laterCompatible` as True cannot itself prove that the packet lacks one. `laterAlternatives` merely displays 0 and 1 as distinct permitted completions of this chosen abstraction. It is auxiliary, never a direct proof of actual later reliability or of a general epistemic theorem.

`populationCompletion` adds 36 hypothetical identical omitted amounts to the known cohort sum. K-03 (generated P04) says the 36 dispatch records and extrapolation method are absent. L-01 says the population is 40 but only four are represented. `populationAlternatives` uses missing amounts 0 and 1 cent to exhibit totals 50000 and 50036. The source imposes no positive minimum amount, so zero is not ruled out; choosing 1 and 2 instead would also differ. Neither completion is asserted as historical fact. The witness is auxiliary to the bounded documentary nondetermination finding.

# Limits and review

No source authenticity, external legal compliance, real-world acceptance, later event outcome, or qualitative rating is formalized. All data are literal synthetic-record transcriptions. The compiler initially required an explicit finite case split to synthesize exception decidability; this local model issue was repaired before final harness validation. Independent semantic review of this audit has not occurred. A self-review compared each definition, inequality, and theorem target against the cited passages before the final check.
