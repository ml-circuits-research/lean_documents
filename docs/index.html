The product contract

Input: any finite number of authorized source documents, a supplied report, and optional review instructions. Without instructions, derive explicit criteria from each finding and the sources. Output: a claim-by-claim audit with evidence and reasoning, formal proofs or refutations where justified, and explicit support gaps. The original report is always visible to the auditor. Writing a new substantive report is outside the product scope.

A report can contain correct findings, false findings, reasonable but unsupported findings, and matters that cannot responsibly be formalized. The skill must preserve those distinctions rather than assign a single “mathematically correct” badge to the report.

  1. Freeze inputs and scope
  2. Extract report findings and sources
  3. Build argument and model
  4. Attempt proof and refutation
  5. Audit meaning and explain verdict

Three useful conclusions

  • Supported: these passages and rules justify this precisely scoped finding; any formal guarantee states its assumptions.
  • Refuted: this relevant counterexample or argument contradicts the finding; the exact failing step is explained.
  • Insufficient support: the reviewed material does not provide the needed argument. This is an audit finding even when the proposition might still be true.

Conflicting evidence, disputed interpretations, and nonformal assessments remain explicit alternatives. The scope of a search is part of the result, not an incidental implementation detail.
