Tests that matter

Behavioral checks must show that the skill explains a real counterexample, distinguishes unsupported claims from false ones, notices negation and exceptions, rejects circular arguments, and preserves conflicting testimony. Technical checks must reject stale artifacts, changed sources, unbuilt modules, unapproved dependencies, and fabricated checker success. A clean package validator alone cannot establish these behaviors.

For the initial curated set, every material claim must have a disposition and every formal success must have a reproducible artifact. Any false formal-certainty result blocks release until explained and corrected. Other disagreements are reviewed by a human evaluator; a small fixture set does not support population-level precision claims.

Authorized implementation scope

Approval of this plan authorizes implementing the skill in skills/ and running local fixture audits in temporary workspaces, within existing access and execution permissions. Tool installation or external access remains subject to the environment's permissions. No publication, external transmission of sensitive sources, or unrelated repository changes are implied.

Known limits and open configuration

  • Each audit pins a Lean version. Lean 4.24.0 is tested with core Init/Std and reviewed local modules; optional checker compatibility and provenance are recorded.
  • Agree per-claim and per-run budgets; stopping means unresolved coverage, not a forced verdict.
  • Specify permitted temporary root, export destination, and retention policy for confidential inputs.
  • Choose where independent checker availability is required versus reported as an optional assurance level.
  • Schedule domain-expert review of fixtures before treating editorial expectations as benchmark truth.
