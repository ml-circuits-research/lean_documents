Traceability contract

Keep meaning, evidence, and proof separate

The central artifact is an argument graph whose leaves point to source passages and whose inference steps can be reviewed or formalized individually.

Semantic record contract

The implemented finding schema combines claim, evidence, argument and outcome fields. Source locations live in the indexed corpus; model meanings and semantic review are companion records. The conceptual records below describe the information to preserve, rather than requiring one file per record type.

RecordRequired information
DocumentStable ID, role (source/report/brief), original path, hash, version, language, type, dates, extraction tool/version, original-to-extracted position map, access classification.
Source statementID, exact quote, original anchor, attributed speaker, assertion/norm/hypothesis/fiction status, polarity, modality, event time vs publication time, scope, exceptions, uncertainty, alternative readings.
Report claimID, report quote and position, atomic normalized proposition, parent finding, quantifier/domain, severity from brief, citations actually supplied by the author.
Check obligationID, linked claim, precise question, target proposition, planned method, premises, applicable version, exclusions, progress, search scope and budget, coverage state.
ArgumentPremise IDs, source evidence, rule IDs, inference steps, rebuttals, dependency edges, missing premises, cyclic dependencies, counterexample and scope when present.
ModelID/hash, symbol legend, source-to-symbol mapping, domain, interpretation branch, assumptions and exceptions, target identity, non-vacuity checks, data provenance.
Proof runRun ID, exact source/dependency hashes, toolchain, command and target, exit code, stdout/stderr, theorem name/type, audited axioms, checker result, elapsed time, resource limit.
Audit findingAll linked IDs; evidence/argument/formal/review states; human explanation, limitations, support gaps, suggested correction or evidence request. Proof reference is null if no proof exists.

Independent state axes

  • Evidence: SUPPORT_ONLY, COUNTEREVIDENCE_ONLY, BOTH, NEITHER. These describe relevant documentary support, not metaphysical truth.
  • Argument: SUFFICIENT_UNDER_ASSUMPTIONS, INSUFFICIENT_SUPPORT, INVALID_INFERENCE, DISPUTED_INTERPRETATION, NON_FORMAL_ASSESSMENT.
  • Formal check: NOT_ATTEMPTED, PROVED, NEGATION_PROVED, COUNTEREXAMPLE_CHECKED, FAILED, TIMEOUT, BLOCKED. Record exactly which proposition was checked.
  • Semantic review: PENDING, ACCEPTED_WITH_LIMITS, CHANGES_REQUIRED. Acceptance records the reviewer and scope; it does not establish source truth.
  • Coverage: PLANNED, REVIEWED, UNRESOLVED, EXCLUDED_WITH_REASON. Coverage is independent of whether a claim was proved.

Public labels such as PROVED_IN_MODEL and REFUTED_IN_MODEL are derived only after the verification gate passes for the actual report claim or its negation. CONFLICTING_EVIDENCE, INSUFFICIENT_SUPPORT, UNDETERMINED, FORMALIZATION_BLOCKED, and NON_FORMAL_ASSESSMENT remain available. Several observations may apply to one finding: a source conflict and an unsupported interpretation should not erase one another.

A theorem proving that a report's argument is insufficient receives its own check ID. It does not cause the report's underlying claim to be labeled REFUTED_IN_MODEL. Likewise, a theorem proving contradictory testimony does not prove both testimony claims true.

  "missing_premises": ["Reliable evidence of absence in the relevant interval"],

  "not_established": ["Approval existed", "Approval did not exist"]
}

Large corpora and change tracking

Ingest every authorized document into a disk-backed inventory. Chunk by headings, paragraphs, tables, and pages while retaining original coordinates. Retrieve relevant context for each finding and also scan the global inventory for versions, annexes, exceptions, and potential counterevidence. Retrieval ranking cannot establish completeness.

Use dependency edges to invalidate affected extractions, models, and results when a source hash, rule, interpretation, or target changes. Reuse a result only when all relevant content and toolchain fingerprints match. Cross-document entity merges require explicit evidence; similar names alone are insufficient.

No fixed count limit means the architecture accepts a finite manifest without an arbitrary document cap. It does not promise unlimited computation, complete ingestion of corrupt files, or a conclusive verdict within every budget. Record every unprocessed input and its impact.
