Theorem counts include direct and auxiliary results. The same theorem can support multiple related atomic findings, and a compound finding can require several results. Auxiliary proofs show facts such as a missing inference or contradictory testimony; they do not settle an unknown event.

Implemented capabilities

The skill directs claim extraction, documentary argumentation, model selection, semantic review and honest delivery. The Python helper prepares temporary workspaces, preserves source hashes and anchors, checks exact quotations, builds explicit Lean modules, checks theorem target types and axioms, rejects stale artifacts, renders audits and exports reproducible bundles. Its indexed engine also handles native DOCX, PDF and OCR, original coordinates and uncertainty, resumable processing and changed-source invalidation. Semantic interpretation remains agent work. Validation method and independence

Each selected report was audited in its own temporary workspace. Initial auditing agents were instructed not to access expected answers, alternate reports or prior reviews. Some agents were reused for unrelated dossiers due to the session thread limit; no agent audited both variants of the same dossier or a dossier whose expected answers it had authored. Shared filesystem access was not a security boundary. The coordinator reviewed source-to-model correspondence and was familiar with fixture design. The independent review record describes additional checks and any corrections.

Limits

A compatible lean4checker was built and actually used for selected fresh environment replays; per-run proof results distinguish passed replay from not run. It uses the same Lean kernel, not an independent kernel implementation. Source authenticity and interpretation are not established by Lean. Calendar offsets are cross-checked against Gregorian calculations outside Lean. Native adapters and a 1,000-source ingestion benchmark were exercised; OCR corrections are attributed review actions, not machine-certified fidelity. Source-code filters are defensive checks, not a sandbox for hostile Lean programs. The historical preparation-only fixture briefs are superseded for these runs by the user’s later execution authorization, recorded separately in every workspace.
