Native documents, larger corpora and retained revisions

The skill preserves original files, records how each passage was extracted, and separates document-processing progress from the evidence needed to judge a report claim.

Inspect before trusting extracted text

Every indexed passage points back to original bytes and their SHA-256 hash. Native PDF passages and OCR output carry extraction uncertainty. Before a direct formal verdict uses an uncertain source or report passage, the auditor must inspect the original and record a review tied to both the source hash and the full extracted passage hash. The tool checks those bindings; the act of inspection remains an attributed human or agent judgment.

Real test scans exposed incorrect timestamps and a TSV parser failure on a literal opening quote. The parser was repaired and regression-tested. Visually corrected text is added with a new anchor through transcribe; original OCR text, images, coordinates, the reviewed transcription and old proof attempts stay available. A correction does not silently overwrite evidence or make incomplete ingestion complete.

A request and its retained files

python3 /path/to/skill/scripts/audit.py doctor --lean /absolute/path/to/lean
python3 /path/to/skill/scripts/audit.py prepare --indexed \
  --brief brief.md --report report.docx --sources dossier/ \
  --temp-root tmp --max-documents 20
python3 /path/to/skill/scripts/audit.py resume --workspace WORKSPACE --max-documents 20
python3 /path/to/skill/scripts/audit.py search --workspace WORKSPACE \
  --query 'exception OR supersedes' --limit 20 --offset 0

The coding agent reads the selected report and sources, constructs the arguments and models, then runs the checking and rendering helpers. The scripts do not autonomously decide documentary meaning. Each request gets a distinct directory under Git-ignored tmp/; no automatic cleanup occurs.

Resource and coverage decisions

Snapshotting fixes the entire authorized source inventory first. Extraction can then stop on a budget and resume. A partial or blocked document needs either further work or an explicit acknowledgement explaining its impact on the affected claims. An acknowledgement never supplies the missing premise. Search results carry their total matching-chunk count and pagination, but the auditor must still examine applicability, versions, exceptions and evidence against the claim.

The executed synthetic load test ingested 1,000 source documents plus a brief and report: about 39 MB of source text, 24,002 passages, and a 108 MB index. It completed in about 25 seconds in this environment with about 138 MiB peak process RSS, across five extraction batches. It retrieved an exception near the end of the corpus and verified that a no-op resume preserved the index hash. These measurements describe ingestion and retrieval, not semantic audit accuracy or a general performance guarantee. Actual measurement record.

When a document changes

python3 /path/to/skill/scripts/audit.py refresh --workspace WORKSPACE \
  --document-id D00005 --replacement revised-policy.pdf --temp-root tmp

A new revision archives earlier reports and proof logs and records the changed hashes. All proof results require a new execution. Semantic claims are all invalidated unless a complete declared dependency map supports a narrower set; even then, explicit evidence dependencies must be included. The reviewer records which affected claims were reconsidered against the current revision before publishing another result. An executed negative control changed the delegation expiry in a copy of a completed audit: the parent remained unchanged, old outputs were archived, and stale rendering plus the revision-review gate rejected reuse. This deliberately altered case stops before re-audit and is not counted as a completed report audit.

For an interrupted write, ordinary verification rejects stale derived files. Explicit resume --recover verifies preserved originals, archives interrupted state, rebuilds extraction and requires fresh review. It refuses to bless a changed original or catalogue.

Packaging and prerequisites

Copy the entire skills/evidence-to-proof-review/ directory. Its scripts use Python standard-library and sibling modules; the examples and evaluator are not runtime dependencies. These optional helpers use Python with SQLite FTS5, Lean with Lake for proofs, Poppler for built-in PDF extraction, and Tesseract plus relevant language data for built-in OCR. The method can also run with the agent’s document tools and Lean alone. Agent extraction import preserves original hashes and coordinates for other formats. Each run pins a stable Lean version; 4.24.0 is the tested default. See the flexibility review. DOCX needs no office installation or pip package. The optional checker must match the Lean version. Installation is explicit; the skill does not download dependencies automatically.

This machine has tested local Lean, Poppler and English OCR tools. Other languages require their corresponding Tesseract data. Local extraction and checking work without network after installation; the coding agent may use a remote service. Self-contained packaging does not mean bundled system binaries or autonomous semantic judgment.
