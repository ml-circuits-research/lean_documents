Begin with a claim whose conclusion is correct but whose offered rule is false. Follow the exact report text, original evidence, inferred question, Lean target and recorded result. This is an executed current-contract example, not a hypothetical workflow.

The skill audits an existing report. The agent reconstructs documentary meaning and writes the formal model; Lean checks the resulting propositions. The preparation command alone does not perform that semantic work.

1. Read the supplied claim and its argument

A is eligible for release. A is signed, and a signature alone is sufficient for release.

This is R3 in the mixed report. It contains a conclusion, an observed premise and a proposed general rule. They need separate checks. The other report is an alternative test input, never evidence for this one.

2. Return to the original sources

Read the original HTML. Line 8 requires a row to be both active and signed. Line 9 records A as active and signed. Line 10 records B as quarantined and signed. The rule and both rows are needed: inspecting only A would miss the defect in the argument.

See the source-to-symbol map and review acceptances. The HTML was processed through an agent-produced extraction; original hashes, line coordinates and material review are retained. Review acceptance is an accountable inspection record, not a machine proof of faithful reading.

3. Infer the questions without a separate brief

  1. Does A meet both conditions in the supplied rule?
  2. Is the report's signature-only rule true for the relevant rows?
  3. Does the report cite or state accurate premises?

Do not assume the report's general rule just because the author uses it. Read the plan and the criteria and argument items. The domain is this stock snapshot; the model does not authorize a real shipment.

4. Choose a proof and a counterexample

-- The conclusion is supported.
Stock.eligible Stock.a

-- The report's proposed rule has an actual in-domain counterexample.
Stock.b ∈ Stock.rows ∧ Stock.b.signed = true ∧ ¬ Stock.eligible Stock.b

The second target is about B and the proposed general rule. It does not refute A's eligibility. A deduction using a false rule may still have a valid inference form: the defect here is the offered rule, not modus ponens itself.

5. Inspect the reviewed model and actual Lean checks

Data and rule definitions · Theorems and proofs · Recorded exact-target and axiom checks.

The helper rebuilds the reviewed local modules, compiles exact target assertions and inspects theorem dependencies. Read the target files and logs linked under C3's formal evidence. A declaration check and an exact-target check can refer to the same theorem; check counts are not counts of independent real-world conclusions.

6. Read the two verdicts together

Read the complete audit and coordinator review. The fixture was deliberately designed; this is not a blind estimate of real-document accuracy.

7. Compare neighboring outcomes

  • C1: supported conclusion and adequate argument — counted stock is 45.
  • C2: refuted conclusion — all-row arithmetic is 60, but archived stock must be excluded.
  • C4: unsupported history and invalid inference — missing historical records do not establish that clearance never occurred; two admissible histories disagree.
  • Correct report, separately executed audit — a correct statement can still have no supplied derivation. Arguments elsewhere in the same report must be considered.

8. Follow the rest of the learning path

  1. Run with Lean and agent tools alone: see exactly which metadata checks were agent-reviewed instead of automated.
  2. Native document correction and changed verdicts: inspect OCR, stale-result rejection and renewed proof checks.
  3. Overlapping intervals and half-cent ties: distinguish defined boundary rules from assumptions.
  4. Coverage matrix: separate current audits, legacy demonstrations, mechanism tests and untested limits.
